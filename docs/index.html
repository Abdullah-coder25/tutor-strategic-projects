Expansion Radar: letting the fleet tell sellers where the next robot goes

Nearly a third of the organizations that received Tutor robots in the past year were existing customers adding more. The robots already record the signals that come before that: hours worked past the booked shift, uptime, falling remote assists, idle lines next door. This prototype turns those signals into a weekly list for account owners, with a drafted note for each site and a backtest that checks whether the signals actually came before past expansions.

All fleet data on this page is synthetic. Account names are invented and the numbers come from a generator, so the results show that the pipeline works, not what predicts expansion at Tutor. The backtest is the tool for finding that out on real data.

Does it see expansions coming? (backtest)

Every week, every site is scored using only data up to that week, then checked against which sites added a robot in the next weeks. The same test runs on a control fleet where expansions are random: if the score looked good there too, it would be fooling us.

What I'd do with real data

  • Run the 10-site comparison on real sites that did and didn't expand. If no signal separates them, stop here.
  • If some do, refit the weights on the full history and keep the ones that hold up in later months.
  • Pilot with two account owners for a quarter: how many flagged sites turned into a conversation, a quote, a second robot.
  • Track seller time saved, and hours added per flagged account, against accounts worked the usual way.
